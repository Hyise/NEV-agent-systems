# 阶段一代码审查记录

审查范围：后端 API、数据校验与持久化，前端状态和页面结构，本机启动/停止脚本，以及研究归档边界。

## 本轮已处理

- 将原本集中在 `App.vue` 的六个业务页面拆为独立视图；应用壳只负责导航、全局上下文和新建项目对话框。
- 将请求、版本切换、文件导入和脏数据保护集中到 `workspace.ts`，避免页面各自复制状态同步逻辑。
- 图表配置跟随对应业务视图，`Chart.vue` 只保留 ECharts 生命周期与尺寸适配职责。
- 后端继续保持 `domain.py`（规则）、`store.py`（SQLite）、`research.py`（只读归档）和 `app.py`（HTTP 编排）的边界。
- 研究归档启动时校验 SHA-256，防止来源文件被修改后仍以原归档身份展示。
- 准则名称拒绝电子表格公式前缀与换行，车型名称导出时进行公式注入保护。
- 分页跳转、项目切换、版本切换和未保存准则保护由明确动作封装，不在模板中堆叠业务语句。
- 前端样式按 `foundation.css`、`shell.css`、`components.css`、`pages.css` 四层拆分，并由 `check:design` 约束入口顺序和关键视觉契约。
- 应用壳、六个业务页面和 ECharts 已统一为宋体回退链；青色只表示评论/准则证据，橙色只表示销量/市场响应。
- 根目录双击启动器只编排构建、健康检查和浏览器打开，实际服务进程仍由 `start-local.ps1` 记录和停止。

## 保留的设计取舍

- `workspace.ts` 是前端唯一的页面级协调器，体积高于单个视图，但它集中处理跨页面共享状态和请求竞争令牌；继续拆成多个相互订阅的 store 会增加当前阶段的复杂度。
- `app.py` 保留约两百行路由编排。领域校验、存储和归档读取已经分离，在接口数量较少时再引入多层 service/repository 不会带来实际收益。
- `style.css` 仅保留四层样式导入；共享控件继续使用稳定 class API，避免为纯视觉包装引入额外 Vue 组件。
- ECharts 公共图表块的生产构建体积仍约 530 kB，并产生 Vite 的 500 kB 提示。本轮不提高阈值掩盖提示；后续按实际加载性能决定是否拆分图表模块。

## 已接入算法及后续边界

- 评论标注和模型实验均已作为独立后台任务模块接入，不在 FastAPI 请求线程中同步执行。
- 模型运行绑定项目、准则版本、不可变矩阵快照哈希、算法版本、随机种子和时间切分，不能覆盖研究归档。
- 第二项自适应评估研究应新增独立领域模块和页面入口，通过公共项目/版本标识组合，不修改现有归档适配器。
- 加入多人使用或公网部署前，必须补充鉴权、授权、审计、上传隔离、备份恢复和反向代理配置。

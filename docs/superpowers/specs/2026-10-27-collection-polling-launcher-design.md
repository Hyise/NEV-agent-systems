# 采集轮询与启动入口设计

## 目标

- 采集任务运行期间，后台轮询继续更新进度，但页面主体、加载提示和输入焦点不随每次轮询闪烁。
- 双击启动器及 PowerShell 启动脚本统一以 `127.0.0.1:8029` 作为默认生产地址。
- 保留首次加载和用户主动操作的可见加载反馈，不改变采集任务状态机、轮询频率或后端接口。

## 方案

采用已确认的方案 A：区分前台加载和静默后台轮询。首次进入、手工刷新和控制操作继续使用 `busy`；定时轮询不切换 `busy`，只在请求成功后原子替换概览与任务列表，并继续安排下一次轮询。

启动入口方面，`启动观衡网站.cmd` 显式传入 `-Port 8029`，`start-site.ps1` 与 `start-local.ps1` 的默认端口也统一为 `8029`。README、运行须知和启动脚本契约测试同步采用同一口径。Vite 开发代理继续作为开发配置单独处理，不作为双击生产启动器的地址来源。

## 约束与非目标

- 不引入 SSE、WebSocket 或新的前端依赖。
- 不改变采集轮询间隔、暂停/继续/停止语义和数据库结构。
- 不覆盖或丢弃当前功能分支已有修改。
- 只有在相关测试、前端构建和后端测试通过后，才提交、合并到 `main` 并推送。

## 验收

1. 初次加载时 `busy=true`，加载完成后恢复为 `false`。
2. 存在运行任务时，定时轮询请求进行期间 `busy` 保持 `false`，已有页面不卸载。
3. 轮询完成后概览与任务列表更新，并继续轮询直到任务终态。
4. 三个生产启动入口默认或显式使用端口 `8029`。
5. 文档中的默认访问地址与启动命令一致。

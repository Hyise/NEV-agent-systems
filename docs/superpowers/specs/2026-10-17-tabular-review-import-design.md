# 表格评论导入设计

## 目标

让评论资产工作台直接导入汽车之家评论 CSV、XLSX、JSON 和 JSONL 文件，并将每条记录的“分项评论全文”作为完整评论正文用于查阅和大模型分析。

## 已核对的数据口径

- 样本目录包含 116 个有效 XLSX 文件、103,839 条评论。
- 每个文件都有“评论”和“抓取信息”两个工作表；业务数据位于“评论”工作表，表头在第 1 行。
- 116 个文件使用同一组 14 列表头：`series_id`、`series_name`、`koubei_id`、`show_id`、`specid`、`specname`、`用户名`、`发表日期`、`标题`、`综合评分`、`最满意`、`最不满意`、`分项评论全文`、`详情URL`。
- 所有 103,839 条记录的“分项评论全文”均为非空字符串；3,829 条记录缺少 `koubei_id`，但所有 `show_id` 均存在且全目录唯一。
- 单文件最多 14,183 条、约 15.86 MB，超过旧版 8 MB/10,000 条限制。

## 导入规则

1. XLSX 只读取名为“评论”的工作表；CSV 使用相同表头。
2. `series_id`、`series_name`、`show_id`、`分项评论全文`、`详情URL` 为表格导入的必要字段。
3. `review_id` 优先使用非空 `koubei_id`，否则使用 `show_id`。
4. `source_url` 使用 `详情URL`。
5. 14 列原始值完整保存在 `original_review`；不拆分、不拼接、不改写“分项评论全文”。日期只做稳定 JSON 字符串序列化。
6. 前端原始评论抽屉和后端语义分析优先读取 `original_review["分项评论全文"]`，并继续兼容既有 `feeling_summary`/`contents`。
7. 支持一次选择多个文件。系统先逐文件完成全部校验，再允许确认写入，并按文件汇总可导入、重复和错误数量。
8. 单文件上限 32 MB、单文件最多 20,000 条；解析后的规范化 JSON 上限 128 MB，覆盖已核对样本并保留明确边界。

## 架构

- 后端新增独立的表格文件解析模块，使用 Python 标准库读取 CSV 和 XLSX，避免引入新的运行依赖。
- 新增原始文件校验与确认接口。确认时重新解析同一文件，并使用校验指纹防止校验后内容变化。
- 既有 JSON/JSONL 对象接口继续保留，避免破坏已有调用方。
- 前端 API 层负责传输文件，资产 workspace 独占多文件校验/确认状态，导入对话框只负责交互与展示。

## 失败处理

- 缺少工作表、缺少必要列、无法解码、损坏 XLSX、空文件、超限文件均返回可操作的中文错误。
- 任一文件存在结构错误时，不开放整批确认。
- 所有文件先校验后写入；确认阶段逐文件提交并显示每个文件的结果。若外部并发写入导致指纹冲突，停止后续文件并提示重新校验，已完成文件不会回滚。

## 验收

- 合成 CSV/XLSX 夹具证明字段映射、`koubei_id` 回退、正文完整保留、日期序列化和错误提示。
- 前后端完整测试与构建通过。
- 使用样本目录中的小型真实 XLSX 完成只读解析和网页校验预览，不修改源文件、不在验收步骤确认写入。

# 观衡“研究仪器型工作台”UI 重塑规格

- 状态：待最终设计确认
- 日期：2026-10-15
- 设计方向：方案 A——研究仪器型工作台
- 适用范围：平台首页、评论数据工作台、多准则决策工作台、自适应评估规划页
- 约束 Skill：`frontend-design`、`$emil-design-eng`、`$nev-mcdm-vue`

## 1. 目标与非目标

本轮将观衡从“由细边框组成的研究线框页”重塑为严谨、清楚、可长期使用的研究工具。视觉服务于两类用户：汽车企业分析人员需要快速完成数据和决策工作，研究人员需要确认来源、版本、范围与限制。

成功标准：

1. 首页在一次浏览中讲清楚“评论数据 → 准则证据 → 决策复核”的研究链路，并区分数据基础、研究核心与规划模块。
2. 评论采集与多准则工作台共享同一套壳层语言，但保留独立业务色与独立状态所有权。
3. 高频操作直接、稳定、少动效；抽屉、弹窗和异步状态具有恰当的空间反馈。
4. 桌面和窄屏均能完成现有流程，不改变后端接口、路由、研究数据或业务口径。

本轮不包含：新增业务能力、改写研究结果、引入外部字体或动画库、改变自适应评估“仅规划”的边界、重新组织 workspace/API 所有权。

## 2. 视觉语言

### 2.1 设计性格

关键词为“研究仪器、档案可信、克制精确”。界面避免大面积渐变、玻璃拟态、悬浮卡片墙、无意义编号和营销式口号。层级主要依靠排版、留白、背景明度与少量关键结构线，而不是给每个内容块增加边框。

### 2.2 色彩令牌

| 令牌 | 建议值 | 用途 |
| --- | --- | --- |
| `--canvas` | `#F1F3F2` | 全站研究画布 |
| `--surface` | `#FBFCFB` | 主内容表面 |
| `--surface-raised` | `#FFFFFF` | 对话框、抽屉、需强调区域 |
| `--ink` | `#18231F` | 标题和主要内容 |
| `--muted` | `#66736D` | 说明、元数据 |
| `--line` | `#D7DEDA` | 必要分隔线 |
| `--collection-accent` | `#3F6655` | 评论采集与数据资产 |
| `--mcdm-accent` | `#23616A` | 准则、分析与研究操作 |
| `--market-accent` | `#B65A3A` | 销量、风险和破坏性操作 |
| `--adaptive-accent` | `#6A6580` | 自适应规划模块 |

颜色只表达稳定语义。状态不得只靠颜色；错误、成功、冻结、规划中还需配合文字、图标或结构位置。

### 2.3 字体角色

- 品牌名、页面一级标题、研究章节标题：`SimSun, "宋体", STSong, "Songti SC", serif`。
- 正文、按钮、表单与导航：`"Microsoft YaHei UI", "Microsoft YaHei", "PingFang SC", sans-serif`。
- 数字、版本、日期与指标：正文无衬线字体加 `font-variant-numeric: tabular-nums`，不下载等宽字体。

这保留用户指定的宋体识别，同时避免小字号按钮、密集表格和数字全部使用宋体造成的屏幕阅读负担。ECharts 标题可用宋体，坐标、数值和图例使用正文无衬线字体。

### 2.4 尺寸与表面

- 圆角只设 `4px`、`8px` 两级；状态胶囊可使用全圆角。
- 普通内容区不使用阴影；只给弹窗、抽屉、浮层使用低透明阴影。
- 桌面内容最大宽度约 `1480px`，工作台保持高信息密度。
- 8px 基础间距体系，正文行高不低于 `1.6`。

## 3. 标志性结构：研究证据链

全站唯一标志性图形语言是“研究证据链”，而不是装饰插画：

```text
发现车系 ── 保存原始评论 ── 提取准则证据 ── 权重与情景 ── 市场复核
  采集绿          采集绿           研究青          研究青       市场朱红
```

- 首页用一条真实业务链连接评论采集和多准则研究入口。
- 工作台只在阶段导航、来源说明或交接位置复用，不作为每张卡片的装饰。
- 自适应评估不接入这条链，保持“规划中”与研究材料待接入的明确边界。

## 4. 平台首页

### 4.1 桌面结构

```text
┌──────────────── 顶部品牌与本机状态 ────────────────┐
│ 观衡 / NEV RESEARCH               本机研究版 0.1 │
├───────────────────────────────────────────────────┤
│ 新能源汽车评价研究平台                            │
│ 从公开评论建立可追溯评价证据，并复核市场选择。    │
│                                                   │
│ 01 数据基础               02 研究核心              │
│ ┌ 评论数据采集 ┐ ──────> ┌ 多准则决策系统 ┐       │
│ │ 目录/评论/资产│ 证据链  │ 准则/标注/决策 │       │
│ └──────────────┘         └────────────────┘       │
│                                                   │
│ 03 后续研究：自适应评估系统 / 规划中               │
├───────────────────────────────────────────────────┤
│ 数据仅保存在本机 · 来源与研究边界说明              │
└───────────────────────────────────────────────────┘
```

### 4.2 层级规则

- 多准则系统是主要研究入口，占更大的视觉宽度；评论采集作为上游基础与其并列连接。
- 自适应系统改为低高度规划条，不与两个可用系统等权。
- 每个入口只保留定位、三个能力点、状态和一个明确操作，不展示重复的边框步骤列表。
- 卡片整块可点击，但内部仍保留语义清楚的 `RouterLink` 与可见焦点。
- 首页首屏在 768px 高度下应能看到两个可用入口和自适应规划条的开头。

## 5. 共享工作台壳层

### 5.1 桌面结构

- 侧栏宽度调整为约 `208px`，品牌区更紧凑。
- 导航项使用 Lucide 现有依赖中的线性图标，图标只帮助定位，不取代文字。
- 当前项采用浅色底、左侧 2px 业务色和较强字重；普通 hover 只改变背景/文字，不位移。
- 顶栏显示“系统 / 当前页面”，右侧只保留返回平台或关键全局操作。
- 页面标题区不再与顶栏重复系统名称；只显示当前任务、说明和主要操作。

### 5.2 移动结构

- `<768px` 时侧栏变为左侧抽屉，保留遮罩、Escape 关闭和焦点恢复。
- 抽屉使用 `transform 220ms var(--ease-out)`，关闭略快；减少动效模式下取消位移。
- 页面操作栏改为纵向或可换行布局，数据表在自身容器滚动，页面不横向溢出。

## 6. 评论数据工作台

### 6.1 任务引导

保留“获取数据—管理数据—用于研究”三阶段，但简化为顶部连续阶段轨道：

- 当前阶段明显；已完成阶段展示可追溯数量；下一阶段给出一句可行动提示。
- 不再让阶段轨道、统计摘要和开始采集卡同时争夺主视觉。
- “发现车系并建立采集任务”作为获取数据页的唯一主要操作。

### 6.2 获取数据页

- 顶部用紧凑数据带展示目录批次、已保存评论、异常记录和来源。
- 当前任务存在时优先展示任务进度、所选车系与暂停/继续/停止；不存在时展示清晰空状态与开始按钮。
- 历史任务使用可展开档案表，事件和异常作为从属详情。

### 6.3 管理数据页

- 筛选区与数据表头组成一个连续的资产工具区。
- “查看原文”是行级主要动作，标签/分析状态是可编辑元数据；原始内容无编辑入口。
- 原文抽屉宽屏约 `720px`，从触发方向进入；标题区固定，正文独立滚动。
- 删除保持危险区和二次确认，动效不弱化其不可恢复性。

### 6.4 用于研究页

- 先展示可用评论数、车系数、异常和分析状态，再展示两个研究交接入口。
- 交接入口明确“只传递研究意图，不自动调用大模型”。

## 7. 多准则决策工作台

### 7.1 导航与研究上下文

- 侧栏继续分为“研究准备”和“分析复核”，每项添加稳定图标。
- 研究上下文改为紧凑的工具带：项目选择、模式、月份和准则版本在一行表达；窄屏分组折行。
- 自定义草稿存在未保存修改时，继续禁用会丢失状态的切换，不改变 workspace 规则。

### 7.2 页面层级

- 研究总览突出关键指标、权重证据和本月观察，减少外围容器线。
- 数据中心、准则工作台和评论语义分析采用更明显的“工作区”结构，主操作固定在标题或工具栏右侧。
- 情景、份额和实验页面保持结果无动画默认，图表不加入装饰性入场。
- 数据来源、快照、准则版本与研究限制靠近对应结果，不能只放在页脚。

## 8. 自适应评估规划页

- 保持无表单、无演示数据、无 API。
- 采用单页研究接入说明：需要的材料、待确认口径和后续建设顺序。
- 使用较弱的规划色和“规划中”状态，避免产生功能已开放的误解。

## 9. 交互与动效规范

依据 `$emil-design-eng`：

| 场景 | 行为 |
| --- | --- |
| 高频导航、项目/月份切换 | 不使用入场动画，只做 `120–160ms` 颜色反馈 |
| 按钮按下 | `transform: scale(0.98)`，`120ms var(--ease-out)` |
| 对话框 | 中心出现，`opacity + scale(0.98→1)`，约 `180ms` |
| 侧栏/原文抽屉 | `transform + opacity`，进入 `200–240ms`，退出更快 |
| Toast | 从自身高度轻微进入，不阻塞操作，支持中断 |
| 表格、分析图表 | 默认无入场和重排动画 |
| 键盘触发的高频操作 | 不增加动画延迟 |

统一曲线：

```css
--ease-out: cubic-bezier(0.23, 1, 0.32, 1);
--ease-in-out: cubic-bezier(0.77, 0, 0.175, 1);
```

禁止 `transition: all`、`scale(0)`、超过 300ms 的普通 UI 动画以及没有精细指针媒体查询的 hover 位移动画。只动画 `transform` 和 `opacity`；颜色与边框允许短过渡。

## 10. 代码边界

- `foundation.css`：新令牌、字体角色、焦点、减少动效和基础 reset。
- `platform.css`：首页和自适应规划页。
- `shell.css`：两个工作台共享壳层、导航、顶栏和移动抽屉。
- `collection.css`：评论采集与资产页面特有布局。
- `components.css`：按钮、表单、状态、表格、对话框等共享组件样式。
- `pages.css`：多准则业务页面特有布局。
- `AppBrand.vue`：品牌，不承担业务导航。
- 两个 Workbench 继续分别创建唯一 workspace；视觉改造不移动状态所有权。

不引入新运行依赖。现有 `lucide-vue-next` 足以提供图标，CSS 足以提供所需动效。

## 11. 可访问性与极端内容

- 保留跳转链接、可见焦点、`aria-current`、对话框名称、Escape 关闭与焦点恢复。
- 按钮和导航触控高度不低于 40px；主要移动操作建议 44px。
- `@media (hover: hover) and (pointer: fine)` 内才使用 hover 专属反馈。
- `prefers-reduced-motion: reduce` 时取消位移/缩放，仅保留必要的颜色或透明度反馈。
- 验证长车系名、长项目名、空数据、千条级目录数量、长中文评论、错误提示与 200% 缩放。

## 12. 验收范围

自动化：

```powershell
Set-Location frontend
npm.cmd test -- --run
npm.cmd run check:design
npm.cmd run format:check
npm.cmd run typecheck
npm.cmd run build
```

浏览器至少验证：

- 首页、评论采集三个阶段、多准则七个页面和自适应规划页；
- `1440×900`、`1024×768`、`390×844`；
- 原文抽屉、目录采集对话框、新建研究对话框、移动导航；
- 键盘导航、长内容、空状态、错误状态和 reduced-motion；
- 页面无意外横向滚动，控制台无新增错误。

## 13. 自审结论

本规格不改变业务或数据契约，不新增依赖，不把自适应系统伪装成可用功能。视觉层级与研究流程一致，宋体要求被保留在品牌与研究标题层，同时提高密集工作区可读性。动效仅用于反馈和空间关系，符合高频研究工具的使用场景。

# 观衡双研究系统平台与工作台重设计规格

- 状态：待用户书面复核
- 日期：2026-09-29
- 决策：采用“方案 A：研究平台入口 + 独立研究子系统”
- 当前实现范围：平台入口、多准则决策系统迁移、自适应评估规划页、现有多准则工作台视觉优化

## 1. 背景与目标

观衡当前直接进入新能源汽车多准则决策工作台。随着第二项“自适应评估”研究将在后续接入，现有单应用壳不能清楚表达平台、研究系统和业务页面之间的层级，也容易让两个研究方向共享不应共享的状态和接口。

本次设计在现有工作台之上增加“观衡研究平台”层。用户从统一入口选择多准则决策系统或自适应评估系统；多准则系统保持现有能力，自适应系统本阶段只展示经确认的研究定位和建设状态，不建立业务模型、接口或模拟数据。

同时重设计多准则工作台，减少英文眉题、徽章、图标、圆角卡片和装饰线等模板化表达，让界面更接近严谨、耐用的科研工具。

成功标准：

- 进入根地址时首先看到两个研究系统的入口，而不是直接进入多准则页面。
- 两个研究系统具有独立路由、应用壳和状态边界。
- 平台页和自适应规划页不读取多准则 API。
- 多准则系统的现有数据、准则、情景、份额和实验行为保持不变。
- 工作台的信息层级比当前版本更清晰，装饰元素显著减少。
- 桌面、平板和手机均能完成入口选择与现有多准则流程。

## 2. 范围

### 2.1 包含

- 新增双研究系统平台入口。
- 新增模块注册表，集中描述模块标识、名称、状态、路由和视觉标识。
- 将当前多准则应用壳迁移为独立模块壳。
- 新增自适应评估规划页，明确其尚未接入。
- 增加模块级路由、返回平台和浏览器前进/后退行为。
- 重设计多准则系统的平台栏、导航、研究上下文栏和六个业务页面。
- 保留宋体要求，并针对宋体重新校准字号、行高和字间距。
- 更新设计契约、测试、文档和浏览器验收截图。

### 2.2 不包含

- 不实现自适应评估算法、数据模型、API、Store、图表或业务表单。
- 不编造自适应研究的指标、流程、输入字段和结果示例。
- 不修改多准则后端 API、SQLite schema、研究归档、算法或指标口径。
- 不加入登录、权限、云同步、多人协作或公网部署能力。
- 不引入微前端、多仓库或两套独立构建系统。
- 不下载网络字体，不引入装饰性动画库。

## 3. 信息架构

```text
观衡研究平台
├── 多准则决策系统（已开放）
│   ├── 研究总览
│   ├── 数据中心
│   ├── 准则工作台
│   ├── 情景分析
│   ├── 份额分析
│   └── 实验档案
└── 自适应评估系统（规划中）
    └── 系统规划页
```

平台和研究系统的职责不同：

- 平台层只负责模块发现、进入、返回和模块状态表达。
- 多准则模块负责现有研究项目、准则版本、数据与结果。
- 自适应模块本阶段只负责诚实表达建设状态和已确认的研究方向。
- 共享层只包含无业务状态的品牌、基础控件、排版和可访问性能力。

## 4. 路由与生命周期

新增 `vue-router` 作为唯一新增的运行依赖。采用 Hash 路由，避免修改当前只在 `/` 返回前端入口文件的 FastAPI 静态服务行为。

| 地址 | 页面 | 行为 |
| --- | --- | --- |
| `/#/` | 研究平台入口 | 启动脚本每次打开根地址时默认进入此页 |
| `/#/mcdm` | 多准则决策系统 | 延迟创建现有 workspace 并读取多准则 API |
| `/#/adaptive` | 自适应评估规划页 | 不发送任何研究 API 请求 |
| 未知地址 | 平台入口 | 替换到 `/#/`，不显示空白页 |

模块页面使用异步加载，入口页不下载 ECharts 和六个多准则业务页面的代码块。多准则模块首次进入时才创建 workspace。模块在同一浏览器会话中使用 `KeepAlive` 保留项目、月份、页面和未保存草稿状态；返回平台不会伪造保存，也不会清空草稿。

浏览器后退从研究系统返回平台，前进可以回到离开前的研究系统。刷新 `/#/mcdm` 可直接恢复多准则模块，但重新从启动器打开无 Hash 的根地址时始终进入平台入口。

├── modules/
│   └── mcdm/
│       ├── McdmWorkbench.vue       多准则模块壳
│       ├── workspace.ts            多准则跨页状态与动作
│       ├── api.ts                  多准则 HTTP 与类型
│       └── views/                  六个现有业务页面

    ├── platform.css

    ├── components.css

依赖规则：

```text
App/router ──> platform metadata
          ├──> MCDM module ──> MCDM workspace/api
          └──> adaptive introduction（无业务依赖）

shared components/styles <── platform 与各模块
```

- `platform/modules.ts` 只保存静态模块元数据，不导入 workspace、API 或业务视图。
- `McdmWorkbench.vue` 是唯一创建并提供多准则 workspace 的组件。
- 多准则视图只能依赖本模块的 workspace/API 和共享展示组件。
- 自适应规划页不得导入任何多准则文件。
- 后续接入自适应研究时，新建独立 `modules/adaptive/`；不向多准则 workspace 添加条件分支。
- 文件迁移以职责为依据，不建设只有一行转发逻辑的包装层。

## 6. 平台入口设计

入口页是研究系统目录，不是营销首页，也不使用两张常见的渐变功能卡。

### 6.1 桌面结构

```text
┌──────────────────────────────────────────────────────────┐
│ 观衡研究平台                  新能源汽车评价研究 · 本机版 │
├──────────────────────────────┬───────────────────────────┤
│ 多准则决策系统               │ 自适应评估系统            │
│ 已开放                       │ 规划中                    │
│                              │                           │
│ 用户评论与销量               │ 研究材料待接入            │
│        ↓                     │        ↓                  │
│ 准则—权重—情景模型           │ 业务口径待确认            │
│        ↓                     │        ↓                  │
│ 份额比较与实验复核           │ 后续功能建设              │
│                              │                           │
│ [进入多准则系统]             │ [查看系统规划]            │
└──────────────────────────────┴───────────────────────────┘
```

路径图是入口页唯一的识别性图形：多准则区域展示已经成立的“输入—方法—输出”证据路径，自适应区域展示“材料接入—口径确认—功能建设”的建设路径。节点只表达已知事实，不使用漂浮粒子、无意义连线、渐变光晕或循环动画。

多准则区域使用较高对比度并提供主要入口。自适应区域保持可点击，但以低一档对比度和“规划中”文字说明当前状态；按钮名称固定为“查看系统规划”，不能使用“开始评估”。

### 6.2 自适应评估规划页

规划页只包含：

- 系统名称和“规划中”状态。
- 已确认事实：系统来源于另一项自适应评估研究，研究代码尚未接入。
- 当前阶段说明：等待研究材料、业务对象和输入输出口径确认。
- 返回研究平台的明确操作。

页面不得展示虚构流程图、示例指标、完成百分比、演示数据或不可用表单。

### 6.3 移动结构

小于 `768px` 时两个模块纵向排列。多准则模块在前，自适应模块在后；每个入口的证据路径保持从上到下阅读。页面本身不能横向滚动，主要按钮占可用宽度但不固定在屏幕底部。

## 7. 多准则工作台重设计

### 7.1 壳层

工作台由三层组成：

1. 平台栏：返回研究平台、模块名称、本机版状态。
2. 研究上下文栏：项目、观察月份、准则版本、工作模式和必要操作。
3. 模块导航与页面内容：六个多准则业务页面。

移除当前重复的英文眉题、阶段标签、双色装饰轨道和侧栏长说明。平台栏与上下文栏不能同时重复当前页面标题。

### 7.2 导航

- 桌面使用约 `176px` 的文字侧栏，减少图标依赖。
- 菜单按真实工作关系分为“研究准备”和“分析复核”，不使用伪造的完成阶段。
- 当前项由字重、文字色和一条短竖线表达，不使用大面积填充底色。
- 返回平台位于模块名称附近，不混入六个业务页面列表。
- 手机端使用带可访问名称的抽屉，关闭后焦点回到触发按钮。

### 7.3 上下文与页面标题

项目、月份、版本和工作模式进入紧凑的稳定工具栏，不再放在独立悬浮卡片中。页面标题缩小为工作标题，标题右侧只放当前页的主要操作。

示意：

```text
研究总览                                      导出研究快照
当前项目 / 2025-12 / 准则 V1 / 预置研究
──────────────────────────────────────────────────────────
页面主要内容
```

长项目名必须截断并通过原生标题或可访问说明展示完整名称。项目或版本存在未保存修改时，沿用当前保护逻辑，不因路由切换丢失草稿。

### 7.4 六个页面

- 研究总览：保留紧凑指标行；权重图和数值表/观察说明形成主要证据区域；减少“卡片中的卡片”。
- 数据中心：数据表成为页面主体；数据集名称、记录数、导入导出和搜索组成一条工具区。
- 准则工作台：按文档编辑器组织版本、状态和准则行；用分隔线代替每条准则的独立卡片。
- 情景分析：控制项集中在图表上方；图表占据主要画布；详细数值按需展开。
- 份额分析：真实份额、模型估计和差值保持同一阅读顺序；继续用文字、符号和数值共同表达差异。
- 实验档案：基线与消融表格共享列结构；研究限制在表格前集中说明，不使用装饰徽章强调归档身份。

## 8. 视觉系统

### 8.1 色彩

| 角色 | 色值 | 用途 |
| --- | --- | --- |
| 平台底色 | `#F4F6F7` | 平台与工作台画布 |
| 数据表面 | `#FFFFFF` | 表格、图表和编辑区域 |
| 主墨色 | `#18232D` | 标题、正文和关键数值 |
| 次级文字 | `#65717C` | 说明、时间和来源 |
| 结构线 | `#D6DCE0` | 分区、表格和控件边界 |
| 多准则识别色 | `#235F68` | 多准则入口、主要操作和当前状态 |
| 自适应识别色 | `#625C82` | 自适应入口及未来模块识别 |

颜色不使用渐变。模块识别色只出现在入口、当前状态和关键操作，不铺满内容区域。错误、警告和成功状态另用符合可访问对比度的语义色，不能借用模块识别色。

### 8.2 字体

继续遵守全站宋体要求：标题、正文、控件、数据和 ECharts 使用 `SimSun`、`宋体`、`STSong`、`Songti SC`、`serif` 回退链。

- 正文默认不小于约 `15px`，行高不低于 `1.65`。
- 删除大部分全大写英文、微型英文眉题和夸张字间距。
- 数字右对齐并启用 `font-variant-numeric: tabular-nums`，不切换成代码字体。
- 页面只保留四级明确字号：平台标题、页面标题、区块标题、正文。

### 8.3 表面与间距

- 默认圆角控制在 `2–4px`，对话框可略高，但不形成“圆角卡片墙”。
- 普通内容区不使用阴影；对话框和浮层只使用一档克制阴影。
- 优先使用留白、对齐和 `1px` 分隔线组织信息。
- 采用 `4/8px` 间距体系；同级页面共享一致的标题、工具栏和内容起点。
- 不添加装饰性动效；只保留抽屉、对话框和状态切换所需的短过渡，并尊重减少动效设置。

## 9. 状态、错误与边界行为

- 平台入口和自适应规划页不依赖后端；多准则 API 暂时不可用时，用户仍能返回平台和查看自适应规划。
- 异步模块加载失败时显示“模块加载失败”，提供“重新加载”和“返回平台”，不显示空白页。
- 多准则加载、保存、错误和成功状态沿用现有 workspace 语义。
- 从存在未保存准则草稿的多准则页面返回平台时，因模块被保活，草稿不丢失；关闭或刷新页面仍遵守浏览器现有生命周期，不承诺跨会话保存未提交草稿。
- 自适应规划页不显示网络加载态，因为本阶段没有网络请求。
- 入口页不能把“规划中”渲染成禁用到无法聚焦的控件；其链接可以由键盘访问并打开说明页。

## 10. 响应式与可访问性

- `≥1200px`：入口双列；工作台文字侧栏、上下文工具栏和主要分析区同时显示。
- `768–1199px`：入口仍可双列但收紧间距；工作台侧栏压缩，复杂分析区改单列。
- `<768px`：入口纵向排列；工作台使用导航抽屉，上下文控件换行，只有表格容器允许横向滚动。
- 平台入口、模块入口、返回平台和业务导航均有清晰焦点样式。
- 使用语义链接完成路由导航，使用按钮执行保存、导出和打开对话框等动作。
- 当前模块和当前业务页分别使用 `aria-current`，不能只用颜色表示。
- 图表继续提供准确 `aria-label` 和相邻的文字/表格信息。
- 390px 宽度下页面 `scrollWidth` 必须等于 `innerWidth`。

## 11. 验证与验收

### 11.1 自动化门禁

- 扩展 `check:design`，约束平台、模块边界、宋体、色彩、路由入口和禁止的模板化元素。
- 为模块注册表和路由回退增加单元测试。
- 保留 `format:check`、`typecheck`、生产构建和全部后端测试。
- 验证平台入口和自适应规划页加载期间没有多准则 API 请求。
- 验证多准则 workspace 只在首次进入模块时创建。

### 11.2 浏览器矩阵

至少在 `1440×1000`、`1024×768` 和 `390×844` 验证：

- 根地址进入平台，两个研究系统入口均可被键盘访问。
- 进入多准则、返回平台、浏览器后退/前进和刷新行为正确。
- 进入自适应规划页后没有业务请求和伪造功能。
- 多准则六页正常、空、错误和长文本状态没有回归。
- 未保存准则草稿在返回平台再进入后仍然存在。
- 页面无整体横向溢出，控制台无未处理异常和意外 404/500。
- 减少动效设置有效，焦点在抽屉和对话框关闭后正确恢复。

### 11.3 视觉验收

- 不再出现大面积圆角卡片墙、渐变、玻璃拟态和无意义科技装饰。
- 删除现有英文眉题、证据轨道和重复状态徽章后，信息含义仍然完整。
- 平台页能够区分多准则系统的真实证据路径与自适应系统的建设路径，而不是用纯装饰掩盖状态差异。
- 六个页面共享结构纪律，但图表、表格和编辑器仍按各自任务形成差异。

## 13. 已接受的取舍

- 选择平台入口加独立模块壳，不采用单工作台顶部切换，避免未来两个研究方向共享业务状态。
- 不采用微前端；当前本机单体部署没有独立发布、团队或技术栈需求。
- 采用 Hash 路由，保持 FastAPI 静态服务和现有 API 不变；地址中的 `#` 是当前阶段为部署简单性接受的代价。

# 观衡新能源汽车研究平台 · 设计基线 V0.6

## 已确认的产品边界

- 用户：汽车企业分析人员与研究人员。
- 软件主体：三个平级功能子系统。评论数据采集和多准则决策已开放，自适应评估保留独立入口并在材料审核后接入。
- 研究主体：当前可运行内容为用户评论驱动的新能源汽车多准则决策；不以多准则数据代替自适应研究。
- 工作模式：预置十项准则快速分析；自定义准则完整研究。
- 核心成果：评价概率矩阵、PNS语义值、BEAST综合效用、理性混合权重、准则相对权重、车型选择份额及实验报告。
- 数据来源：用户提供的销量及加工数据，以及在实验室授权范围内采集的汽车之家公开口碑。当前不建设专用脱敏模块。
- 软著拟登记人为一人。身份、姓名及开发日期在材料准备阶段填写，不自动推断。

## 本次可运行交付：阶段一

实现前后端工作台，使用真实研究归档数据，支持项目创建、模式切换、月度数据查询、车型搜索、权重曲线、归档预测比较、实验结果查看、准则草稿编辑/冻结/派生新版本、按冻结准则导入加工CSV、CSV与JSON导出。平台另提供独立评论采集系统：先异步发现并原子发布前 1000 个唯一车系目录，再由用户选择车系创建不可变任务快照；同时支持完整原始口碑、任务控制、断点续采、查询和 JSONL 导出。

历史预测和归档指标仍只读展示，不伪装成新训练或新推理。系统已新增独立模型实验链路，可对冻结准则绑定的当前加工矩阵运行 Ridge、随机森林、XGBoost、LightGBM 和 BEAST-MCDM 修复版；新结果保存在版本化运行记录中，不覆盖原研究档案。评论标注到月度概率矩阵的自动聚合、登录权限和 Word/PDF 报告仍在后续阶段实现。

## 输出口径

1. 真实份额：当前数据集中某月车型销量 / 同月入选车型销量总和。它是样本内份额，不自动等于全国市场份额。
2. 模型输出：给定月度准则概率和压力条件下，候选车型集合内的选择份额。加入/移除候选车型可能改变归一化结果。
3. 企业浏览时搜索车型仅过滤显示，不重新定义分母，也不重新推理。
4. 归档预测只包含2025年11、12月；其他月份展示真实数据并明确没有预测，不插值补造。
5. 输入包含当月评论特征，因此先定位为条件份额估计/历史解释。未来月份预测需另行定义预测时点、可用信息和特征构建，不能把同期拟合当未来销量预测。
6. 理性权重是模型中BEV与心理抽样的混合系数，不是对真实消费者理性程度的直接测量。
7. 准则权重来自效用范围归一化；当前模型实际聚合为各准则效用之和除以总范围，不能另加一次权重而改变研究公式。
8. 归档权重报表经过EMA平滑，理性权重末点另有趋势修正。界面和导出注明这是后处理报表；后续新运行同时保留原始值和展示值。
9. 时间压力只用于2025年及以前的历史观察，关联曲线不作为政策因果效应证据；2026年起有效时间压力固定为0，不再形成压力差异。

## 两种模式与版本约束

| 项目项 | 预置研究分析 | 自定义准则研究 |
| --- | --- | --- |
| 准则 | 研究模型使用的10项、42个等级 | 用户定义准则与有序等级 |
| 初始数据 | 来源包的1609条车型月记录 | 空数据集，可导入加工CSV |
| 准则修改 | 派生为新的自定义项目 | 草稿可修改，冻结后只可派生新版本 |
| 模型 | 历史档案只读；可另建修复版模型实验 | 导入绑定冻结版本的加工矩阵后可运行新实验 |
| 兼容规则 | 原始等级代码和顺序保留 | 数据集绑定某一冻结准则版本 |

预置等级使用数据中的L0…L(n-1)，按当前PNS代码的效用从高到低排序。来源JSON中的自然语言标签与模型存在等级数不一致，因此作为待核验的原始标签展示，不把缺失标签猜成真实标签。自定义准则也按照“由优到劣”的顺序定义。

冻结是一项真实状态变更：至少1项准则，每项2～8个唯一、非空等级；准则名称唯一，最多20项；冻结后编辑接口拒绝修改。派生新版本不移动已有数据集、结果或模型，新版本必须重新绑定数据。每次保存采用revision防止多窗口覆盖。

## 数据流及关键对象

项目 → 准则版本 → 数据集版本 → 运行配置 → 模型版本 → 分析结果 → 报告。

- 项目：名称、工作模式、创建时间。
- 准则版本：项目ID、版本号、草稿/冻结状态、revision、准则顺序、等级顺序。
- 数据集：项目ID、准则版本ID、内容哈希、导入时间、车型月份记录、来源信息。
- 模型实验版本：准则版本、不可变矩阵快照哈希、时间切分、预处理参数、随机种子、模拟次数和实现版本。
- 模型实验任务：待运行、运行中、成功、失败、取消；保存进度、错误、测试预测和指标。

CSV必需列：产品型号、观察区间、时间压力、Real_Sales，以及与当前准则同名的列。观察区间允许YYYY-MM或同月的“YYYY-MM ~ YYYY-MM”。时间压力列为兼容历史数据继续保留：2025年及以前必须填写0～1，2026年起允许留空并统一按0进入数据集、模型和导出。每个准则单元格是JSON对象，键严格为L0…L(n-1)，值有限、非负且总和为1；不依赖JSON对象原始键顺序。

导入拒绝重复车型月份、无效月份、空车型、负销量、历史月份压力缺失或越界、历史同月不同压力、月度总销量为零、缺失准则和概率维数不匹配。2026年起忽略原始压力输入并保存有效值0。保存前统一验证，失败不写数据库。

## 平台与前端信息结构

平台使用 Hash 路由提供四个稳定路径：`#/` 为功能系统目录，`#/collection` 为评论采集工作区，`#/mcdm` 为多准则工作台，`#/adaptive` 为自适应评估规划页。模块名称、状态和路径由统一注册表维护。平台层不依赖采集或研究 workspace/API；采集与多准则工作区分别由模块壳独占并通过 `KeepAlive` 保留页面状态。历史模块路由取舍见 [ADR-0001](ADR/0001-双研究系统平台与模块路由.md)，采集独立化见 [ADR-0002](ADR/0002-评论采集作为独立平台子系统.md)，目录发现与评论任务解耦见 [ADR-0003](ADR/0003-车系目录发现与评论任务解耦.md)。

评论采集工作区包含总览、采集任务、车系和原始评论四页。“新建任务”采用 01 发现车系、02 选择并采集的两步流程：目录刷新独立运行并保留旧版本，任务创建后只读其规范化快照。采集数据是平台级共享只读资产：多准则和未来自适应研究可按稳定 ID 选择数据，但各自拥有大模型输出、人工修订和评估状态，不回写 `original_review`。

| 页面 | 核心操作 | 第一阶段真实能力 |
| --- | --- | --- |
| 研究总览 | 选项目/月份，查看准则重要度、数据范围 | 真实归档统计、下一阶段说明 |
| 数据中心 | 浏览、搜索、导入、导出 | 预置数据与自定义加工CSV |
| 准则工作台 | 新建自定义项目、编辑等级、冻结、派生 | 持久化准则版本与校验 |
| 情景分析 | 切换理性权重/准则权重、选择准则 | 归档月度后处理曲线 |
| 份额分析 | 比较真实与归档估计、搜索车型 | 样本内份额，明确可用月份 |
| 评论语义分析 | 配置日期/车系/样本，实时运行、复核并形成矩阵 | 任务与逐条结果实时联动，矩阵缺失项显式阻塞 |
| 模型实验 | 建立可执行实验、查看进度/切分/指标；展开原归档 | 可读取评论任务生成的不可变矩阵，新结果与只读历史档案严格分区 |

自适应评估系统当前仅显示“研究材料待接入—业务口径待确认—后续功能建设”，不提供伪造的表单、指标或演示结果。材料到位后先补业务与数据契约，再建设独立页面、状态和后端接口。

企业与研究用户共用信息结构，通过页面中的简洁说明和研究口径补充满足两者需求。阶段一以本机单用户为范围，不出现虚假的登录或角色切换。

## 技术边界

- 前端：Vue 3 + TypeScript + Vite，ECharts绘图，自定义轻量组件样式。
- 后端：FastAPI + Pydantic，SQLite 保存项目、准则、加工数据、采集任务断点和原始评论，文件保存不可变研究归档。
- 采集：Playwright 负责动态车系发现和临时会话，HTTPX 负责结构化评论分页；单工作线程串行限速，不使用 Celery/Redis。
- 原研究代码：只归档到algorithms/reference，不自动导入执行；产品算法在后续独立适配。
- 开发：Vite /api代理。构建后FastAPI直接提供前端静态站点，单端口本机运行。
- 长任务：目录发现、评论采集和月度销量采集各有进程内单工作线程，但共享一个外部访问协调器，绝不并发访问外部汽车平台。模型实验使用另一个进程内单工作线程和不可变数据快照，不复用采集线程。应用重启将活动发现和销量任务标记为失败、活动评论采集转为暂停、活动模型实验标记为失败并保留记录。
- 扩展：未来为第二项研究建立独立模块边界；在材料确认前不提前建立其业务页面、状态、API 或数据库字段。

## 分阶段验收

### 阶段一：业务与数据基础（本次）

通过API和真实浏览器验收：真实归档加载、项目隔离、正确分母、没有预测的月份保持空状态、自定义草稿重载后仍在、冻结后不可改、派生版本不误用旧数据、非法CSV拒绝、导出来源可追溯、两步式车系选择、完整评论详情与窄屏可用。实网目录结构漂移等未通过项必须保留在验收记录，不以受控夹具替代实网结论。

### 阶段二：修复并接入研究算法

- 保留旧结果为研究归档，修复版另设模型版本，禁止覆盖研究基线。
- 时间顺序训练/验证/测试，训练和选参不接触测试月份。
- 统一语言标签、等级代码、矩阵和模型维数；形成可审核映射表。
- 补齐原始评论标注到概率矩阵的标签映射、销量关联、概率归一化。
- 检查评估指定1000次模拟但固定抽样缓存只有200次的问题。
- 检查条件性悲观分支中对标量最小值再次取min/max导致阈值退化的问题。
- 检查B样条边界p=1和压力公式与现有加工数据的差异。
- 修正Ridge用概率平均值作为特征导致每准则接近常数的基线问题。
- 统一消融实验的极差温度及其他控制变量，必要时各变体独立重训。
- 新结果与历史档案并存；不承诺复现旧R²或必须优于所有基线。

验收：合法输入可训练、取消、推理；输出份额有限非负且和为1；无时间泄漏；同一版本/种子可复现；模型拒绝不兼容准则。

### 阶段三：评论研究处理流程

评论采集、原始数据资产、月度销量采集、LLM 准则发现、候选审核、逐评论封闭标注、失败重试和评论结果到月度矩阵的显式构建已经接入。任务运行期间前端同步进度和逐条结果；结束后按冻结准则统计车型月份等级概率，并在缺失日期、准则或销量时阻止写入。销量记录支持平台分离、同月评论车系精确匹配、查询和导出；懂车帝与易车仍需正式接口或可审计授权访问方式，当前不绕过人工验证。后续重点是人工复核抽样及更长时间范围的实验数据建设。只有用户明确启动在线分析时调用外部 LLM；研究输出单独保存并引用评论 ID/内容哈希，不修改采集原始对象。

### 阶段四：正式交付与软著资料

完善报告、安装与运行说明、操作手册和实际截图，记录真实完成日期、版本和权利人。是否加入登录/多人协作以部署需求决定。完成研究原型到可用软件的功能验收后，再整理软著材料。

## 视觉设计记录

主题：汽车市场研究工作台。页面中心是十项准则的横向权重比较，数值与车型表保持可直接比读。

- 色板：研究画布#F3F5F6、数据表面#FFFFFF、正文#1E2B38、结构线#D9E0E5、评论/准则青#0F7C82、销量/市场橙#C65A3A。
- 字体：标题、正文、数据和图表统一采用SimSun/宋体/STSong/Songti SC回退链，不下载网络字体。
- 布局：浅色侧栏与项目上下文固定，主体使用低阴影数据面板；研究流程带展示当前交付能力，不做虚假进度条。
- 比较过多卡片的指标墙与集中式分析画布后，选择后者：权重谱是第一视觉落点，统计仅作为横向辅助信息。
- 减少装饰渐变和无意义动画；支持键盘焦点、低动态偏好、图表旁数值数据。
# 评论语义处理阶段（已实现）

流程为“选择已采集评论 → 稳定分层样本 → 分批发现线索 → 全局归并候选 → 人工审核并冻结 → 逐条评论封闭标注 → 实时结果复核 → 月份车系矩阵预览 → 显式生成数据快照 → 模型实验”。系统不自动启动 BEAST 或生成新销量预测，最终实验仍由研究人员确认参数后手动运行。

准则发现按完整评论边界建立可恢复批次检查点，暂停后仅继续未完成批次；候选方案绑定任务创建时的草稿 revision，避免覆盖任务运行期间的人工编辑。前端保留任务历史、车系搜索分页、标注筛选分页、汇总和失败项重试入口。

评论级标注按车型—月份聚合冻结等级概率，但仍属于模型辅助研究数据，不表述为人工真值。后续阶段需补充人工复核抽样、跨平台销量匹配审核、模型评估与数据版本迁移。

# 新能源汽车情景多准则决策分析系统 · 设计基线 V0.3

## 已确认的产品边界

- 用户：汽车企业分析人员与研究人员。
- 研究主体：用户评论驱动的新能源汽车多准则决策。第二项自适应研究后续接入。
- 工作模式：预置十项准则快速分析；自定义准则完整研究。
- 核心成果：评价概率矩阵、PNS语义值、BEAST综合效用、理性混合权重、准则相对权重、车型选择份额及实验报告。
- 数据来源：用户提供的汽车平台评论、销量及加工数据。第一版不建设爬虫和专用脱敏模块。
- 软著拟登记人为一人。身份、姓名及开发日期在材料准备阶段填写，不自动推断。

## 本次可运行交付：阶段一

实现前后端工作台，使用真实研究归档数据，支持项目创建、模式切换、月度数据查询、车型搜索、权重曲线、归档预测比较、实验结果查看、准则草稿编辑/冻结/派生新版本、按冻结准则导入加工CSV、CSV与JSON导出。

阶段一的预测和实验页面展示来源包内已有结果；不会伪装成新训练或新推理。自定义项目在导入自身数据前保持空状态；自定义项目没有归档模型结果。LLM在线调用、模型训练、重新评估、登录权限和Word/PDF报告在后续阶段实现。

## 输出口径

1. 真实份额：当前数据集中某月车型销量 / 同月入选车型销量总和。它是样本内份额，不自动等于全国市场份额。
2. 模型输出：给定月度准则概率和压力条件下，候选车型集合内的选择份额。加入/移除候选车型可能改变归一化结果。
3. 企业浏览时搜索车型仅过滤显示，不重新定义分母，也不重新推理。
4. 归档预测只包含2025年11、12月；其他月份展示真实数据并明确没有预测，不插值补造。
5. 输入包含当月评论特征，因此先定位为条件份额估计/历史解释。未来月份预测需另行定义预测时点、可用信息和特征构建，不能把同期拟合当未来销量预测。
6. 理性权重是模型中BEV与心理抽样的混合系数，不是对真实消费者理性程度的直接测量。
7. 准则权重来自效用范围归一化；当前模型实际聚合为各准则效用之和除以总范围，不能另加一次权重而改变研究公式。
8. 归档权重报表经过EMA平滑，理性权重末点另有趋势修正。界面和导出注明这是后处理报表；后续新运行同时保留原始值和展示值。
9. 时间压力关联曲线不作为政策因果效应证据。

## 两种模式与版本约束

| 项目项 | 预置研究分析 | 自定义准则研究 |
| --- | --- | --- |
| 准则 | 研究模型使用的10项、42个等级 | 用户定义准则与有序等级 |
| 初始数据 | 来源包的1609条车型月记录 | 空数据集，可导入加工CSV |
| 准则修改 | 派生为新的自定义项目 | 草稿可修改，冻结后只可派生新版本 |
| 模型 | 当前展示历史归档，不执行旧训练脚本 | 后续接入训练，无默认权重可复用 |
| 兼容规则 | 原始等级代码和顺序保留 | 数据集绑定某一冻结准则版本 |

预置等级使用数据中的L0…L(n-1)，按当前PNS代码的效用从高到低排序。来源JSON中的自然语言标签与模型存在等级数不一致，因此作为待核验的原始标签展示，不把缺失标签猜成真实标签。自定义准则也按照“由优到劣”的顺序定义。

冻结是一项真实状态变更：至少1项准则，每项2～8个唯一、非空等级；准则名称唯一，最多20项；冻结后编辑接口拒绝修改。派生新版本不移动已有数据集、结果或模型，新版本必须重新绑定数据。每次保存采用revision防止多窗口覆盖。

## 数据流及关键对象

项目 → 准则版本 → 数据集版本 → 运行配置 → 模型版本 → 分析结果 → 报告。

- 项目：名称、工作模式、创建时间。
- 准则版本：项目ID、版本号、草稿/冻结状态、revision、准则顺序、等级顺序。
- 数据集：项目ID、准则版本ID、内容哈希、导入时间、车型月份记录、来源信息。
- 后续模型版本：准则结构指纹、训练数据集ID、时间切分、预处理参数、随机种子、代码版本。
- 后续任务：待运行、运行中、成功、失败、取消；保存进度、错误与输出产物。

CSV必需列：产品型号、观察区间、时间压力、Real_Sales，以及与当前准则同名的列。观察区间允许YYYY-MM或同月的“YYYY-MM ~ YYYY-MM”。每个准则单元格是JSON对象，键严格为L0…L(n-1)，值有限、非负且总和为1；不依赖JSON对象原始键顺序。

导入拒绝重复车型月份、无效月份、空车型、负销量、非有限数值、压力越界、同月不同压力、月度总销量为零、缺失准则和概率维数不匹配。保存前统一验证，失败不写数据库。

## 前端信息结构

| 页面 | 核心操作 | 第一阶段真实能力 |
| --- | --- | --- |
| 研究总览 | 选项目/月份，查看准则重要度、数据范围 | 真实归档统计、下一阶段说明 |
| 数据中心 | 浏览、搜索、导入、导出 | 预置数据与自定义加工CSV |
| 准则工作台 | 新建自定义项目、编辑等级、冻结、派生 | 持久化准则版本与校验 |
| 情景分析 | 切换理性权重/准则权重、选择准则 | 归档月度后处理曲线 |
| 份额分析 | 比较真实与归档估计、搜索车型 | 样本内份额，明确可用月份 |
| 实验档案 | 基线/消融比较、来源说明 | 归档结果和方法待修复项 |

企业与研究用户共用信息结构，通过页面中的简洁说明和研究口径补充满足两者需求。阶段一以本机单用户为范围，不出现虚假的登录或角色切换。

## 技术边界

- 前端：Vue 3 + TypeScript + Vite，ECharts绘图，自定义轻量组件样式。
- 后端：FastAPI + Pydantic，SQLite保存项目、准则和加工数据，文件保存不可变研究归档。
- 原研究代码：只归档到algorithms/reference，不自动导入执行；产品算法在后续独立适配。
- 开发：Vite /api代理。构建后FastAPI直接提供前端静态站点，单端口本机运行。
- 长任务：后续使用独立worker/Celery，训练不放在请求进程中。
- 扩展：未来通过输入矩阵、情景配置、模型输出协议接入第二项研究，不提前建立其页面或数据库字段。

## 分阶段验收

### 阶段一：业务与数据基础（本次）

通过API和真实浏览器验收：真实归档加载、项目隔离、正确分母、没有预测的月份保持空状态、自定义草稿重载后仍在、冻结后不可改、派生版本不误用旧数据、非法CSV拒绝、导出来源可追溯、窄屏可用。

### 阶段二：修复并接入研究算法

- 保留旧结果为研究归档，修复版另设模型版本，禁止覆盖研究基线。
- 时间顺序训练/验证/测试，训练和选参不接触测试月份。
- 统一语言标签、等级代码、矩阵和模型维数；形成可审核映射表。
- 补齐原始评论标注到概率矩阵的标签映射、销量关联、概率归一化。
- 检查评估指定1000次模拟但固定抽样缓存只有200次的问题。
- 检查条件性悲观分支中对标量最小值再次取min/max导致阈值退化的问题。
- 检查B样条边界p=1和压力公式与现有加工数据的差异。
- 修正Ridge用概率平均值作为特征导致每准则接近常数的基线问题。
- 统一消融实验的极差温度及其他控制变量，必要时各变体独立重训。
- 新结果与历史档案并存；不承诺复现旧R²或必须优于所有基线。

验收：合法输入可训练、取消、推理；输出份额有限非负且和为1；无时间泄漏；同一版本/种子可复现；模型拒绝不兼容准则。

### 阶段三：完整评论研究流程

接入评论和销量导入、LLM准则提取、标签人工审核、标注缓存/重试、矩阵构建。只有用户明确启动在线分析时调用外部LLM。先解决来源JSON与训练等级的映射，避免错误标注进入训练。

### 阶段四：正式交付与软著资料

完善报告、安装与运行说明、操作手册和实际截图，记录真实完成日期、版本和权利人。是否加入登录/多人协作以部署需求决定。完成研究原型到可用软件的功能验收后，再整理软著材料。

## 视觉设计记录

主题：汽车市场研究工作台。页面中心是十项准则的横向权重比较，数值与车型表保持可直接比读。

- 色板：研究画布#F3F5F6、数据表面#FFFFFF、正文#1E2B38、结构线#D9E0E5、评论/准则青#0F7C82、销量/市场橙#C65A3A。
- 字体：标题、正文、数据和图表统一采用SimSun/宋体/STSong/Songti SC回退链，不下载网络字体。
- 布局：浅色侧栏与项目上下文固定，主体使用低阴影数据面板；研究流程带展示当前交付能力，不做虚假进度条。
- 比较过多卡片的指标墙与集中式分析画布后，选择后者：权重谱是第一视觉落点，统计仅作为横向辅助信息。
- 减少装饰渐变和无意义动画；支持键盘焦点、低动态偏好、图表旁数值数据。

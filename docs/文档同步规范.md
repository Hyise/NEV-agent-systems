# 文档同步规范

## 1. 文档职责与事实来源

| 文档 | 负责回答 |
| --- | --- |
| `README.md` | 这是什么、当前能做什么、如何进入运行与治理文档 |
| `运行须知.md` | 如何准备、启动、停止、备份和排障 |
| `系统设计与实施路线.md` | 产品边界、业务口径、阶段路线和验收目标 |
| `API与数据契约.md` | HTTP 路径、字段、状态、数据规则 |
| `开发与架构规范.md` | 代码职责、依赖方向和工程约束 |
| `测试与质量门禁.md` | 什么变更需要什么验证证据 |
| `Skill使用清单.md` | 编码代理何时加载哪些 Skill |
| `阶段一验收记录.md` | 特定版本实际完成过的验收证据 |
| `ADR/` | 重大架构选择、备选方案和后果 |

代码与测试是当前行为证据，契约和设计文档解释预期。二者冲突时不得只修改文字掩盖问题：先确认正确口径，再让实现、测试和文档在同一变更中一致。

## 2. 代码变化到文档的映射

| 变化 | 必须检查/更新 |
| --- | --- |
| 新增或修改 API、字段、状态码 | `API与数据契约.md`、前端共享类型、相关测试 |
| 改变数据来源、指标、分母、月份或研究限制 | `系统设计与实施路线.md`、README 当前能力/限制、界面说明、验收测试 |
| 新增环境变量、依赖、端口、启动/停止方式 | `运行须知.md`、README、示例命令 |
| 改变模块职责或依赖方向 | `开发与架构规范.md`；重大选择新增 ADR |
| 改变验证命令或质量要求 | `测试与质量门禁.md`、AGENTS 常用命令 |
| 安装、删除或改变 Skill 触发条件 | `.agents/skills/SOURCES.md`、`Skill使用清单.md`、必要时 AGENTS 路由 |
| 改变用户流程、导航或视觉结果 | 操作说明、相关截图和浏览器验收记录 |
| 完成路线图阶段 | `系统设计与实施路线.md`、对应验收记录、README 版本和能力 |

“检查”不等于每次都改；若确认不受影响，在交付说明中简要记录即可。

## 3. 编写规则

- 中文描述业务与操作，代码标识、命令、字段名和路径保持原样。
- 明确区分：已实现、已归档、计划、限制、假设。不要把路线图写成当前能力。
- 命令必须从注明的工作目录可执行；Windows 命令优先使用 PowerShell 形式。
- 不记录秘钥、个人凭据、临时进程号或只能在某次会话使用的 URL。
- 外部来源给出原始链接、获取日期和本地用途；不大段复制第三方说明。
- 截图只用于展示真实运行状态，更新后删除或明确标注已经失效的截图引用。
- 链接使用相对路径，标题稳定且能独立说明内容；不保留 `TODO`、空链接或未经验证的数字。

## 4. 同步流程

1. 开始变更时用上表确定受影响文档。
2. 实现与测试完成后，同一批次更新文档；不要靠“以后补文档”的记忆。
3. 搜索旧术语、旧版本、旧端口和占位符，检查 README 到详细文档的导航。
4. 运行文档中新增或改变的命令；无法运行时明确写出环境前提和未验证原因。
5. 在交付摘要中列出文档变化和仍有效的已知限制。

## 5. ADR 与历史记录

ADR 记录当时为何做出重大选择，接受后不直接重写结论；后续改变用新 ADR 标记旧 ADR 被替代。验收记录同样是版本证据，不因后来功能变化而改写成“始终如此”，应新增对应阶段的记录。

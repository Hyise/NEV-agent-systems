# 测试与质量门禁

## 1. 基本规则

- 功能与缺陷修复先添加能证明行为的失败测试，再写最小实现；纯文档、格式化和无行为的机械重命名可直接验证。
- 测试使用临时数据库和受控样本，不读写 `.runtime/platform.sqlite3`，不依赖公网，不覆盖研究归档。
- 完成声明必须包含本次实际运行的命令、结果和未运行项。历史通过记录不能替代当前验证。

## 2. 变更类型与最小门禁

| 变更类型 | 必须执行 |
| --- | --- |
| 仅 Markdown/Skill | 链接与占位符检查；受影响 Skill 的 `quick_validate.py`；核对文档中的命令和路径 |
| Python 领域、存储或 API | 相关失败测试转绿；完整后端 pytest |
| Vue/TypeScript 非视觉逻辑 | `format:check`、`typecheck`、`build`，以及相关逻辑/浏览器流程 |
| 样式、布局、交互、图表 | 全部前端门禁；真实浏览器桌面和窄屏验证；检查控制台与网络失败 |
| 数据口径、导入、导出或版本规则 | 后端完整测试；前端完整门禁；代表性业务流程；同步契约文档 |
| 依赖或构建脚本 | 后端与前端完整门禁；全新环境安装/构建可行性；许可证与版本说明 |
| 安全修复 | 回归测试、攻击/拒绝路径测试、对应完整门禁；必要时重新威胁建模 |

若一个变更属于多类，取并集，不选择最轻的一项。

## 3. 标准命令

从项目根目录执行后端测试：

```powershell
python -m pytest backend/tests -q
```

当前已验证机器可明确指定：

```powershell
& 'E:\anaconda927\envs\py311\python.exe' -m pytest backend/tests -q
```

前端门禁：

```powershell
Set-Location frontend
npm.cmd run format:check
npm.cmd run typecheck
npm.cmd run build
```

Skill 结构校验：

```powershell
$env:PYTHONUTF8 = '1'
& 'E:\anaconda927\envs\py311\python.exe' 'E:\aaaxz\codexhome\skills\.system\skill-creator\scripts\quick_validate.py' '.agents\skills\nev-mcdm-vue'
```

最后一条依赖当前 Codex 本机工具目录，只用于维护 Skill；普通运行用户无需执行。Windows 默认 GBK 可能无法读取 Skill 中的 UTF-8 标点，所以校验时显式启用 UTF-8。

## 4. 后端测试覆盖重点

- 正常路径：项目、准则草稿/冻结/派生、导入、分页、查询、导出和研究归档读取。
- 边界与拒绝路径：空值、重复准则、非法概率、非有限数值、超大文件、错误编码、未知资源、冻结后修改。
- 并发与隔离：过期 `revision` 冲突；不同项目/版本的数据不串联；测试间数据库隔离。
- 数据口径：份额分母、月份排序、等级键映射、归档可用月份和指标来源。
- 安全属性：路径遍历、异常文件名、错误信息泄漏、未支持媒体/结构和未来鉴权边界。

单元测试适合纯解析和校验；API `TestClient` 测试负责验证路由、状态码、响应 schema 与存储协作。不要只断言 200，应断言关键业务结果。

## 5. 前端与浏览器验证重点

- 首屏、项目切换、六个业务页面、月份和查询筛选、分页、准则保存/冻结/派生、CSV 导入和导出。
- 加载、空数据、4xx/5xx、慢请求覆盖与重复点击；过期响应不能覆盖最新选择。
- 对话框焦点恢复、键盘操作、可见焦点、图表 `aria-label`、颜色之外的信息表达。
- 桌面与窄屏下导航、表格、图表、按钮和错误提示可用；允许数据表自身水平滚动，不允许整页意外溢出。
- 浏览器控制台无未处理异常，关键 API 无意外 404/500，下载文件名和内容符合约定。

## 6. 完成定义

一项变更只有在以下条件都满足时才算完成：需求可演示；新增/修改行为有测试或明确人工证据；适用门禁通过；没有遗留占位符和调试代码；文档影响已处理；研究结论与来源表述准确；未执行项和已知风险已向审核者说明。

提交前还应执行 `git diff --check` 与 `git status --short`，确认暂存范围完整且不含运行数据、构建产物、凭据或无关变更。Git 检查用于验证提交边界，不能替代代码测试。

# 观衡系统运行须知

本文用于本机演示、功能评审和软著材料截图。启动后首先进入三个平级功能子系统的平台入口，只监听本机地址，不是可直接上线的公网版本。

## 1. 运行范围

- 访问地址：<http://127.0.0.1:8018>
- 接口文档：<http://127.0.0.1:8018/docs>
- 数据库：`.runtime/platform.sqlite3`
- 服务日志：`.runtime/server.out.log`、`.runtime/server.err.log`
- 默认端口：`8018`，只绑定 `127.0.0.1`

入口中的“评论数据采集系统”和“多准则决策系统”已可使用；“自适应评估系统”当前仅展示建设规划，不含评估表单、结果或后端接口。

系统没有登录和权限控制。请勿把端口映射到公网，也不要把 `.runtime` 中的本机研究数据提交到公共仓库。

## 2. 已准备环境的启动与停止

最方便的方式是在项目根目录双击：

```text
启动观衡网站.cmd
```

启动器会依次完成以下动作：

1. 优先选择项目 `.venv`，其次选择当前机器已验证的 Python 3.11 环境。
2. 当前端需要重新构建时，在 `frontend` 目录核对已安装依赖；依赖缺失或版本不一致时自动执行 `npm install`。
3. 当前端源码或依赖清单比 `frontend/dist` 新时自动执行生产构建。
4. 启动本机服务并等待健康检查通过。
5. 使用默认浏览器打开 <http://127.0.0.1:8018> 的研究平台入口。

重复双击不会重复拉起服务。停止时双击 `停止观衡网站.cmd`。

根目录的两个 `.cmd` 会调用 Windows 自带的 Windows PowerShell 5.1；包含中文提示的启动/停止脚本必须保持 **UTF-8 with BOM** 编码，避免旧版 PowerShell 误解码。浏览器安装脚本使用纯 ASCII 提示，可直接由 Windows PowerShell 5.1 执行。停止脚本会兼容 Windows PowerShell 5.1 与 PowerShell 7 对 JSON 日期的不同解析方式，并在目标进程已经退出时自动清理失效的 `.runtime/server.json`。

PowerShell 等价命令：

```powershell
Set-Location 'E:\aaaxz\daima1022\软著\nev-mcdm-platform'
.\scripts\start-site.ps1
```

不希望自动打开浏览器时：

```powershell
.\scripts\start-site.ps1 -NoBrowser
```

### 2.1 测试尚未合并到 `main` 的功能分支

Git 分支不需要推送到 GitHub，也不需要先合并到 `main`，即可在本机运行生产构建。测试当前 `feat/raw-review-reader` 分支时，必须从该分支对应的 worktree 启动：

```powershell
Set-Location 'E:\aaaxz\daima1022\软著\nev-mcdm-platform\.worktrees\raw-review-reader'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-site.ps1 -Port 8029
```

启动后访问 <http://127.0.0.1:8029/#/collection>。脚本会在该 worktree 中检查依赖、按需执行 Vite 生产构建，并由 FastAPI 提供构建后的页面。命令中的 `-ExecutionPolicy Bypass` 只对本次新建的 PowerShell 进程生效，不会永久修改系统或当前用户的执行策略。

停止该分支的本地服务：

```powershell
Set-Location 'E:\aaaxz\daima1022\软著\nev-mcdm-platform\.worktrees\raw-review-reader'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\stop-local.ps1
```

该 worktree 使用自己的 `.runtime/platform.sqlite3`，不会自动读取 `main` 工作目录中的本地数据库。使用 `8029` 是为了避免与 `main` 目录默认使用的 `8018` 端口冲突；不要从 `main` 目录的启动器判断该功能分支是否生效。

停止服务：

```powershell
.\scripts\stop-local.ps1
```

停止脚本会核对进程号、启动时间和可执行文件，只停止由启动脚本记录的进程；数据库和研究归档不会被删除。

## 3. 新环境首次准备

建议使用 Python 3.11 和 Node.js 22.12 以上版本。研究压缩包只作为导入源，不会被执行。

```powershell
Set-Location '项目根目录'
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
.\scripts\install-collection-browser.ps1 -PythonExe '.\.venv\Scripts\python.exe'
.\.venv\Scripts\python.exe scripts\bootstrap_research.py --archive 'llm-beast-mcdm(1).zip的绝对路径'
Set-Location frontend
npm ci
npm run build
Set-Location ..
.\scripts\start-local.ps1 -PythonExe '.\.venv\Scripts\python.exe'
```

归档导入采用文件白名单，并在 `backend/data/research/manifest.json` 保存来源压缩包及文件 SHA-256。启动时会复核归档文件哈希；文件被意外修改时，服务会拒绝启动。

## 4. 使用前必须了解

1. “预置研究分析”读取原研究的加工矩阵与报表。图表是归档结果，不是网页重新训练的结果。
2. 原研究训练时间与评估时间存在重叠，因此基线、消融和份额估计仅用于研究复核，不能作为独立测试成绩或未来销量承诺。
3. “自定义准则研究”支持准则编辑、版本冻结、评论语义分析、加工 CSV 导入、数据浏览和模型实验；评论级结果可按月份和车系聚合为不可变评价矩阵，也可继续导入符合当前冻结准则的加工矩阵。
4. 准则等级必须按由优到劣排列。冻结后不可原地修改，只能派生新版本；旧数据不会自动迁移到新版本。
5. 导入文件必须为 UTF-8 CSV，单文件不超过 8 MB、最多 10,000 条车型月份记录。字段和概率格式见 [API与数据契约](API与数据契约.md)。
6. 预置数据来自公开汽车平台，但正式提交或展示前仍应确认平台条款、引用方式和数据使用授权。
7. “返回研究平台”会离开多准则工作台，但当前页面草稿由前端暂存；未保存内容仍应及时保存，不能把内存暂存视为持久化备份。
8. 评论采集分为两步：先主动发现并缓存按 `series_id` 去重的前 1000 个唯一车系，再从当前目录中显式选择采集对象。“功能验证”可选 1～3 个车系、每车系最多 2 页；“正式采集”可选 1～1000 个车系并逐车系采集全部评论。开发、截图和一般验收不得误用正式采集。
9. 正式采集前由实验室确认与汽车之家的授权范围和有效期。系统在列表页、单条口碑详情页和下一分页等相邻请求之间强制等待 2～4 秒，车系之间等待 5～10 秒并保持串行运行；临时请求按 5、15、45 秒退避，连续 3 个车系失败后自动暂停；遇到 403、429、验证页面或响应结构变化立即暂停，不绕过访问限制。
10. 每条评论保留汽车之家列表接口的原始结构化对象，并使用对应详情页 HTML 补齐 `contents[].content` 中被省略号截断的原文；详情页中“空间、驾驶感受、续航、外观、内饰、性价比、智能化”等非空评价区块会按页面原始顺序补入 `contents`，已有分区继续保留 `structuredid` 等来源字段，新分区不虚构来源未提供的 ID。不拆分、不拼接评论，来源地址直接指向详情页。任务、车系、评论和断点均在 `.runtime/platform.sqlite3`；JSONL 导出和 `output/` 截图不得提交 Git。旧版本已经保存的截断或缺项记录不会后台自动联网更新，应重新执行相应采集任务，由同一评论 ID 的幂等更新覆盖。
11. 暂停任务仍显示在“当前任务”区域并阻止创建第二个任务；应先继续或停止，再创建新任务。关闭网站时，运行中的采集会在当前请求结束后转为可恢复的暂停状态。
12. 评论语义分析会把用户明确选择的完整评论文本传输给 DeepSeek API。准则发现只接受自定义草稿；逐条评论标注只接受自定义冻结版本。模型不得创建体系外准则或等级，证据必须是原文子串。
13. 评论数据工作台分为“获取数据—销量数据—管理数据—用于研究”。原始评论不可修改；只能维护标签、备注和分析启用状态。永久删除不提供恢复，删除前已经形成的研究快照仍会保留并标记源评论已删除。
14. “模型实验”会把当前冻结准则与加工矩阵保存为不可变快照，然后在后台严格按月份顺序划分训练、验证和测试集。新运行结果与原研究归档分区展示；不能把新指标称为原论文复现，也不能把样本内份额称为未来销量预测。
15. “销量数据”统一采集全国车系月度零售量并按平台分别保存。汽车之家当前可直接低频运行；懂车帝和易车在自动化环境需要人工验证，选择后会形成受阻步骤供审计，不会绕过验证或写入替代值。

### 4.1 首次建立车系目录

1. 进入“评论数据采集系统”，点击“新建任务”。目录为空时先点击“开始发现”；已有目录时可点击“重新发现”。
2. 发现过程在后台串行运行，页面显示当前页、已扫描条目、唯一车系和跳过数。旧目录在新批次成功发布前始终可浏览。
3. `completed` 表示达到 1000 个唯一车系；`completed_short` 表示数据源正常耗尽但少于 1000 个，两者都可以进入第二步。
4. 点击“取消发现”后采用协作式取消：当前网络请求结束、下一次请求开始前停止。取消或失败不会覆盖上一版目录。
5. 若提示 403、429、验证页面或页面结构变化，停止重试并保留错误记录；确认授权、网络和页面结构后再手动重新发现，不提高频率或绕过限制。

### 4.2 选择车系并创建任务

1. 点击“选择车系并采集”，按车系名称或 `series_id` 搜索；“全选当前筛选结果”覆盖所有匹配分页，不只选择当前页。
2. 选择功能验证或正式采集。两种模式都不会自动取目录前 N 项，必须显式选择。
3. 创建瞬间会把当前目录中的名称、链接、顺序和 ID 固化为任务快照；之后刷新目录不会改变已创建任务。
4. 目录在浏览与提交之间发生变化时，后端会拒绝已失效的 ID。刷新目录并重新选择即可恢复。

例行验证只运行少量真实目录发现和功能验证任务；不得把完整 1000 车系目录的全部评论采集作为启动检查、单元测试或截图步骤。

### 4.3 管理、导入与删除评论资产

1. 在“管理数据”页使用关键词、车系 ID、来源、标签、分析状态和评论时间组合筛选；评论时间是原始评论中的实际发表日期，不是采集或导入时间，起止边界均包含。未设置时间时保留日期缺失的评论，设置任一时间边界后只返回具有有效日期且位于范围内的记录。按 Enter 或点击“应用筛选”后，结果栏会显示命中数量和已生效条件；“清空筛选”恢复全部评论。每条记录均可点击“查看原文”打开右侧详情，窄屏下详情占满屏幕。
2. “原始评论内容”按来源顺序完整展示评论概述及“满意”“不满意”等正文，不做截断、合并或改写；展开“全部原始结构化字段”可复核完整 JSON。“管理信息”只修改标签、备注和是否参与分析，不会改变原文和内容哈希。
3. 人工导入依次执行“选择文件→校验预览→确认写入”。既可以一次选择多个 JSON、JSONL、CSV 或 XLSX 文件，也可以直接选择一个文件夹批量导入；文件夹模式会忽略 Excel 临时文件和不支持的文件。每次最多 800 个文件，每个文件最大 32 MB、最多 20,000 条。没有数据行，或所有数据行的“分项评论全文”均为空时，该文件会在预览中标记为“已跳过 · 没有评论”，不会阻止同批次其他有效文件写入；损坏、缺少必要字段或存在无效评论行的文件仍按错误处理，并阻止确认写入。JSON/JSONL 使用 UTF-8，CSV 支持 UTF-8 和 GB18030，XLSX 读取“评论”工作表。先用 `backend/tests/fixtures/import/reviews-valid.jsonl` 验证；`reviews-invalid.jsonl` 只用于观察错误行，不应确认写入。
4. 汽车之家表格按 `series_id`、`series_name`、`show_id`、`分项评论全文`、`详情URL` 映射；有 `koubei_id` 时优先作为评论 ID，否则使用 `show_id`。全部表格字段保存在只读 `original_review` 中，“分项评论全文”会作为一条完整原文展示和分析，不会拆分或改写。
5. 永久删除必须填写原因并准确输入当前评论 ID。活动采集任务、内容哈希变化或并发管理冲突会阻止删除；先停止相关采集并刷新详情后再决定是否重试。
6. 删除后的墓碑默认阻止相同汽车之家评论静默重采。“允许重新采集”只解除未来阻止，不恢复被删除的原文。
7. “用于研究”显示服务端可分析数量和车系分布。进入准则发现或评论标注只定位多准则页面；仍需人工选择来源范围并点击开始。

### 4.4 采集并核验月度销量

1. 进入“销量数据”，选择开始月份、结束月份和来源平台。研究首轮建议使用 `2026-01` 至 `2026-04`。
2. 任务按“平台—月份”拆成独立步骤。汽车之家每个步骤低频分页读取完整月榜；不要重复点击或同时运行评论目录/评论采集。
3. 懂车帝或易车显示“需人工验证”时可以保留勾选以形成审计记录，也可以取消勾选只采集汽车之家。系统不会代答验证码、复用其他平台数值或把受阻记作零。
4. 任务完成后按平台、月份、车系和匹配状态筛选。只有唯一标准化同名车系自动匹配；“未匹配”“多候选”需人工复核后再用于研究。
5. “导出 CSV”使用当前已应用筛选条件。销量数据库与 CSV 都是本机研究数据，不提交 Git。
6. 例行联网验收只运行一个平台的一个月份；四个月完整任务必须由研究人员明确启动并观察步骤状态。

### 4.5 配置并运行评论语义分析

1. 复制根目录 `.env.example` 为 `.env`，填写 `DEEPSEEK_API_KEY`。默认基础地址为 `https://api.deepseek.com`，模型标识为 `deepseek-flash`。
2. 重启网站。启动脚本仅按字面读取合法 `KEY=VALUE` 行，不执行表达式，也不覆盖已经存在的进程环境变量。
3. 在评论采集系统确认已有完整评论；进入多准则系统的“评论语义分析”。草稿版本先选择车系和样本上限执行“准则发现”，人工审核候选后应用到草稿并冻结。
4. 切换冻结版本，选择 20、100、500 条或全部评论执行逐条标注。首次真实验证建议只选 20 条。
5. 任务可暂停、继续或取消；应用异常退出后遗留任务会转为暂停。已成功或命中缓存的结果不会重复调用。
6. 认证或账户问题会暂停任务。更新 `.env` 后必须重启服务再继续；轮换 Key 时不要把旧 Key 写入文档、日志或数据库。

没有 Key 时，创建大模型任务返回 503；评论采集、研究归档、准则编辑和数据浏览不受影响。

### 4.6 安装并运行模型实验

标准依赖已包含 NumPy、SciPy 和 scikit-learn，可直接运行 Ridge、随机森林和 BEAST-MCDM 修复版。启用 XGBoost 与 LightGBM 时，使用启动网站的同一个 Python 执行：

```powershell
.\.venv\Scripts\python.exe -m pip install -r backend\requirements-model-boosting.txt
```

本机当前工作分支若使用预置 Python 3.11，则执行：

```powershell
E:\anaconda927\envs\py311\python.exe -m pip install -r backend\requirements-model-boosting.txt
```

重启网站后进入“多准则决策系统 → 模型实验”。先确认准则已冻结且数据记录数不为 0，再选择模型、验证月数、测试月数、随机种子和 BEAST 模拟次数。能力卡显示“未安装”时不会创建失败任务；完成依赖安装并重启后会自动变为可选。

一次只运行一个模型实验。活动实验可协作式取消；取消在当前模型结束或进入下一模型前生效。完成记录保存在 `.runtime/platform.sqlite3`，停止或重启网站不会删除。预置 24 个月数据在默认 2 个验证月、2 个测试月下使用最后两个月（2025-11、2025-12）作为测试集。

## 5. 数据备份与重置

需要保留自定义项目时，停止服务后备份：

```text
.runtime/platform.sqlite3
backend/data/research/
```

不要在服务运行时直接编辑 SQLite 文件。评论资产支持有审计的永久删除，但不支持原文恢复；正式删除前应先单独备份数据库。开发与验收删除流程只使用临时数据库或脱敏合成评论，不对正式采集数据演练。

## 6. 常见问题

### 页面提示“请先构建前端”

```powershell
Set-Location frontend
npm ci
npm run build
Set-Location ..
```

若在网站已打开时重新执行前端构建，旧页面可能仍引用上一版动态分包并提示“模块加载失败”。点击页面中的“重新加载”或手动刷新即可载入新构建；这不会修改数据库。

正常使用 `启动观衡网站.cmd` 时，启动器会自动核对并补齐前端依赖。只有手工执行 `start-local.ps1` 或新环境准备时，才需要先自行运行上述命令。

### 页面无法打开

先检查健康接口 <http://127.0.0.1:8018/api/health>，再查看 `.runtime/server.err.log`。若端口被其他程序占用，可换端口启动：

```powershell
.\scripts\start-local.ps1 -PythonExe 'E:\anaconda927\envs\py311\python.exe' -Port 8020
```

此时访问 <http://127.0.0.1:8020>。

如果双击脚本后出现中文乱码、`Unexpected token` 或“字符串缺少终止符”，不要手工删除中文提示；先确认三份 `.ps1` 仍以 UTF-8 with BOM 保存，再运行启动器回归测试：

```powershell
E:\anaconda927\envs\py311\python.exe -m pytest backend\tests\test_launch_scripts.py -q
```

### 评论采集提示缺少 Chromium

Playwright Python 包和浏览器二进制是两个安装步骤。使用运行网站的同一个 Python 再执行：

```powershell
.\scripts\install-collection-browser.ps1 -PythonExe '.\.venv\Scripts\python.exe'
```

该命令可重复执行。浏览器版本由 `backend/requirements.txt` 中锁定的 Playwright 版本决定，不要手工复制其他版本浏览器目录。

### 导入 CSV 失败

先从“数据中心”下载当前准则版本的 CSV 表头模板。检查编码为 UTF-8、月份为 `YYYY-MM`、每项概率均为 `L0` 至 `L(n-1)` 且合计为 1。时间压力列继续保留：2025年及以前必须填写0～1且同月一致；2026年起可以留空，系统会统一按“无时间压力”（有效值0）处理。

### 修改准则后不能切换项目

这是未保存修改保护。请保存草稿、冻结版本，或点击“撤销未保存修改”后再切换。

### 评论任务运行后看不到结果

进入“多准则决策系统 → 评论语义分析”，确认顶部选中的是运行任务时的自定义项目，而不是只读研究归档。系统会记住本浏览器最近使用的项目；如果项目已删除则自动回退到研究归档。

启动逐条标注后，页面每约 1.5 秒同步任务进度、成功/失败数、Token 用量、汇总和第一页评论结果。切换“历史任务”会把下方结果自动限定为该任务。网络中断时保留最后结果，可点击查询或刷新页面重试；刷新不会重新调用模型。

任务完成后，“形成评价矩阵”列出可生成记录以及“生成前需要处理”清单。失败评论可原位点击“重试失败评论”；销量问题会跳转到“数据采集系统 → 销量数据”，并预填月份和评论车系 ID；缺少日期会跳转到“管理数据”并定位原评论，因为原始数据不可修改，需要核对后删除并重新导入或采集；2026 年前压力问题可一键把下一次任务范围调整到 2026-01-01 起。处理完成后返回矩阵并点击“重新读取”。评论没有提及某项准则不是错误：系统采用中性均匀分布，并保存该准则覆盖率，不阻止生成。生成成功后点击“进入模型实验”；模型实验至少需要满足其训练/验证/测试月份数量要求，否则应补充月份数据，而不是缩短数据口径来规避校验。

## 8. GitHub SSH 首次配置

仓库远端使用 `git@github.com:Hyise/NEV-agent-systems.git`。当前开发机的专用公钥位于：

```powershell
$publicKey = "$env:USERPROFILE\.ssh\id_ed25519_nev_agent_systems.pub"
Get-Content $publicKey
ssh-keygen -lf $publicKey -E sha256
```

显示的指纹应为：

```text
SHA256:GvcgPWY8e+4vr++xYlxbtBtlmjWAbbaj7o+kzjTN9ww
```

将公钥添加到 GitHub 账户的 `Settings → SSH and GPG keys` 后，执行：

```powershell
ssh -i "$env:USERPROFILE\.ssh\id_ed25519_nev_agent_systems" -o IdentitiesOnly=yes -T git@github.com
git push -u origin main
```

出现 `Permission denied (publickey)` 表示公钥尚未加入对应 GitHub 账户或仓库无权限。出现主机指纹确认时，应先与 GitHub 官方公布值核对；不要关闭主机校验。完整的密钥保护和轮换规则见 [GitHub SSH 密钥管理](开发与架构规范.md#107-github-ssh-密钥管理)。

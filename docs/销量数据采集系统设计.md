# 销量数据采集系统设计

## 1. 目标与口径

销量采集是评论数据工作台中的独立流程，用于为评论研究补充同一观察月份的车系销量。首期研究范围为 2026 年 1 月至 4 月，统一指标为“全国车系月度零售量”。

- 来源平台：汽车之家、懂车帝、易车。
- 采集粒度：来源平台 × 观察月份 × 平台车系。
- 三个平台的结果分别保存，不求平均、不用一个平台的数据冒充另一个平台。
- 缺失值保持缺失，不转换为零。
- 评论原始数据保持只读；销量记录写入独立数据表。
- 三个平台均声明数据来自“行业综合销量”，因此平台值用于来源核验，不表述为三个独立统计样本。

## 2. 用户流程

评论数据工作台新增“销量数据”入口，流程固定为：

1. 选择起止月份和来源平台。
2. 创建采集任务并查看各“平台—月份”步骤的状态。
3. 系统按月抓取完整榜单，而不是逐车系访问详情页。
4. 系统以评论资产中的车系名称建立匹配候选；精确匹配自动确认，其余保持待复核。
5. 用户查看已入库的来源记录、匹配状态和采集错误，并导出 CSV。

任务允许部分成功。单个平台被验证码、访问限制或页面结构变化阻断时，该步骤记录失败原因，其他平台与月份继续执行。

## 3. 技术边界

`backend/sales_collection/` 独占销量采集：

- `domain.py`：月份、平台、任务状态和来源记录校验。
- `repository.py`：SQLite 表、任务/步骤/记录和评论车系匹配查询。
- `adapters.py`：平台读取边界；不写数据库。
- `service.py`：单工作器、低频调度、分步失败隔离和外部访问预约。
- `api.py`：`/api/sales-collection` HTTP 契约和 CSV 导出。

评论采集、目录发现和销量采集共享 `ExternalAccessCoordinator`，本机同一时间只运行一个外部采集操作。前端由 `salesWorkspace.ts` 独占销量状态，由 `SalesView.vue` 展示，不把销量任务塞入评论 `workspace.ts`。

## 4. 来源策略与限制

### 汽车之家

使用公开车系月销榜分页接口，以每页最多 50 条读取到 `pagecount` 结束。请求固定为全国、车系月榜、零售量，校验返回月份、页码、车系 ID、名称、排名与销量。

### 懂车帝与易车

两平台保留独立适配器和任务步骤。2026-10-19 的低频侦察中，懂车帝在自动化环境只返回应用空壳，易车返回验证码页面。系统不得绕过验证码或伪造来源；遇到该状态时记录 `access_verification_required`，并把平台标记为需人工处理。后续取得正式数据接口或可审计的授权访问方式后，只替换相应适配器。

## 5. 数据与追溯

每条销量记录至少保存：平台、月份、平台车系 ID、平台车系名称、销量、排名、指标口径、来源 URL、采集时间和任务 ID。任务步骤保存请求月份、状态、抓取数量和错误代码。

匹配结果保存评论车系 ID/名称、平台车系 ID/名称、匹配方式和状态。精确标准化名称可自动确认；模糊或多候选匹配不得自动写成已确认。

运行数据、原始响应和 CSV 导出属于本机研究数据，不提交 Git。

## 6. 验收标准

- 可在页面选择 2026-01 至 2026-04 和一个或多个平台创建任务。
- 汽车之家适配器能解析分页响应并去重入库。
- 平台步骤相互隔离，验证码或结构错误不会丢失已成功月份。
- 页面可按平台、月份、车系关键词和匹配状态查询记录。
- CSV 导出与当前筛选口径一致，并防止表格公式注入。
- 真实联网验收仅采集一个月份；完整四个月采集由用户在页面显式启动。

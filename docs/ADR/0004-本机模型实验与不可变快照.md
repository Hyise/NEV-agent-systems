# ADR-0004：本机模型实验与不可变快照

- 状态：已采纳
- 日期：2026-10-18
- 决策范围：多准则模型执行、数据版本和后台任务

## 背景

系统原先只能展示研究压缩包内的基线、消融和预测数值，不能证明网页实际执行过模型。直接运行原压缩包训练脚本会把研究原型的路径、依赖、时间泄漏和已知公式问题带入产品；在 HTTP 请求线程中同步训练又会阻塞整个本机网站。新实验还必须与只读历史归档并存，不能覆盖或伪装成旧结果的复现。

## 决策

1. 新增独立的 `backend/model_experiments` 模块。`app.py` 只组装路由、仓库、单工作线程和数据快照工厂，不承载特征、算法或指标计算。
2. 启动实验时，把冻结准则、当前加工矩阵和来源信息规范化后计算 SHA-256，并在 SQLite 中保存不可变快照。运行记录引用快照、准则版本、模型实现版本、时间切分、随机种子和模拟次数。
3. 采用严格的月份顺序切分：训练集在前、验证集居中、测试集在后。测试月份不参与拟合。所有模型输出均在当月候选车型集合内归一化，要求有限、非负且合计为 1。
4. 首批统一模型契约包含 Ridge、随机森林、XGBoost、LightGBM 和 BEAST-MCDM 修复版。Ridge 使用有序等级的语义期望，不再使用恒定的概率平均值。BEAST 修复版显式处理 `p=1` 的 B 样条边界、按配置生成完整心理模拟样本，并使用记录级条件悲观判断。
5. XGBoost、LightGBM 是锁定版本的可选依赖。缺少依赖时能力接口返回不可用原因，前端禁用对应选项；不得等到后台任务中静默失败。Ridge、随机森林和 NumPy/SciPy 版 BEAST 属于核心依赖，可在标准环境运行。
6. 模型实验由进程内单工作线程串行执行。服务重启时，排队或运行中的记录标记失败并保留错误原因；已完成结果不受影响。该方案仅适用于本机单实例，不宣称是分布式任务系统。
7. 前端“模型实验”与“原研究归档指标”分区展示。新结果只能出现在可执行实验区；历史表格保持只读并明确不是本系统重新运行结果。

## 备选方案

- 直接执行研究压缩包脚本：不能隔离已知缺陷、硬编码路径和环境，且难以形成产品级版本契约，因此不采用。
- 在 FastAPI 请求中同步运行：实现简单，但长模型会阻塞接口且无法记录进度、取消和异常恢复，因此不采用。
- 强制安装所有深度学习和提升树依赖：会显著增加首次安装体积，并让无关功能因一个可选包失败而无法启动，因此采用“核心依赖 + 可选能力显式降级”。
- 覆盖原研究指标：会破坏证据链，也把不同时间切分与实现混成同一口径，因此禁止。

## 结果与约束

- 同一快照、实现版本、配置和随机种子可重新执行并核对。
- 运行记录会增加 SQLite 体积；快照按内容哈希复用，避免同一矩阵重复保存。
- 当前 BEAST 修复版是可执行产品实现，不声称逐位复现原 PyTorch 权重或原论文指标；语义间距学习、完整消融重训和评论标注到月度矩阵的桥接仍需独立验收。
- 取消是协作式的，只在模型边界检查；单个模型内部不会强制终止线程。
- 多实例部署前必须把进程内执行器替换为具备租约、心跳和幂等提交的任务基础设施，并新增 ADR。

# 架构决策记录（ADR）

ADR 用于保存影响范围大、长期成本高或难以回退的架构选择，使后来维护者能理解“为什么”，而不只是看到结果。

## 需要 ADR 的情况

- 更换前后端框架、数据库、部署方式或鉴权边界；
- 引入异步任务、模型训练/推理服务、消息队列或外部平台；
- 改变准则/数据/模型版本策略或执行不可逆迁移；
- 一个选择有多个合理备选，且会约束后续多个模块。

局部重构、样式修正、命名调整和既有规则下的功能实现不需要 ADR。

## 编号与状态

文件名使用四位递增编号和简短主题，例如 `0001-选择SQLite作为阶段一存储.md`。状态只使用：

- `提议`：仍在讨论；
- `接受`：已决定并应执行；
- `拒绝`：方案未采用，但保留理由；
- `已替代`：由新的 ADR 取代，并链接新编号；
- `废弃`：不再适用且没有直接替代。

复制 [0000 模板](0000-模板.md) 创建记录。接受后的 ADR 保留历史，不直接改写原决策；方向变化时新增 ADR 并互相链接。
